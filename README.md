## Стъпките

### Работен цикъл

Всяка задача мина през едни и същи стъпки:

1. Задание (промпт) към AI агента.
2. Генериране на кода.
3. Стартиране с `node`.
4. Сравнение на реалния изход с очаквания.
5. Поправка при разминаване.
6. Commit.

Среда: Node.js 24, чист JavaScript, без външни библиотеки (освен Leaflet за картата).

### Етап 1: Упражнение „Функции и обекти“ (`functions-and-objects/`)

**Задание:** проект с 3 теми по 3 задачи с нарастваща трудност. Темите са: функции и върнати стойности, функции като параметри, анонимни функции и callback-и. Изисквания: условие на български, решение с `return`, поне 3 теста и обекти във всяка тема.

**Резултат:**

| Тема | Лесна | Средна | Трудна |
|------|-------|--------|--------|
| 1. Основи | сбор с параметри по подразбиране | min/max/средно: връщане на масив и обект | „ученическа карта“: функция, която връща обект с методи и `this` |
| 2. Функции като параметри | `calculate(a, b, operation)` | собствени `map` и `filter` | фабрика за валидатори (функция, която връща функция) |
| 3. Анонимни функции | declaration, expression и arrow | `setTimeout` и error-first callback | продукти с `map`, `filter`, `reduce` и `forEach` |

**Проверка:** всеки файл има малка функция `check()`, която печата очаквания и реалния резултат. Пуснати са и деветте файла: **96 от 96 проверки минават**. За асинхронната задача е проверен и редът на изпълнение: синхронният код завършва преди callback-ите.

*Забележка:* текстът на заданието беше прекъснат („методи в…“). Агентът го отбеляза и продължи с разумно допускане, вместо да спре.

### Етап 2: Задачи за SoftUni Judge (`Functions-Objects-Events/`)

**Задание:** 8 задачи. Основното правило е, че в Judge се предава **само една функция**, затова всички помощни функции трябва да са вътрешни.

| Файл | Функция | Какво упражнява |
|------|---------|-----------------|
| `html-snippet.js` | `printAsHTML`, `printHTMLSnippet` | параметри по подразбиране, вътрешна функция |
| `fibonacci.js` | `printFibonacci` | итерация, BigInt |
| `sequence-of-operations.js` | `processOperations` | rest параметри, `for-of`, `if-else`, `break` |
| `filter-numbers.js` | `filterNumbers` | предикати като arrow функции, комбиниран предикат |
| `extract-sentences.js` | `splitSentences` | callback функция |
| `print-objects.js` | `printPersonInfo` | деструктуриране на вложен обект в параметрите |
| `nearest-point.js` | `nearestPoint` | деструктуриране + rest, Евклидово разстояние |
| `geo-area.js` | `calculateGeoArea` | площ на сферичен многоъгълник |

**Проверка:** отделен скрипт пуска всеки файл и сравнява изхода **байт по байт** с очаквания от условието. Резултатът е **8 от 8 съвпадения**, например:

| Задача | Очакван изход | Реален изход |
|---|---|---|
| sequence-of-operations | `42` / `12` / `invalid operation` / `10` | ✅ същото |
| filter-numbers | `253` / `-415` / `532` | ✅ същото |
| nearest-point | `{ x: -5, y: 20 }` | ✅ същото |
| geo-area | `Area: 1384.10 m²` | ✅ същото |

**Фибоначи на три стъпки** (реални измервания, `fibonacci-steps.js`):

| Версия | fib(40) | Бележка |
|--------|---------|---------|
| а) рекурсивна | **1310 ms**, 331 160 281 извиквания | всяко извикване поражда две нови; сложността е експоненциална |
| б) итеративна (Number) | **0.08 ms** | от n = 78 нататък резултатът излиза извън `Number.MAX_SAFE_INTEGER` и губи точност |
| в) итеративна + BigInt | точна и за n = 500 (105 цифри) | **финалната версия за Judge** |

### Етап 3: Интерактивни HTML страници

Към три от задачите има страници, които използват **същата функция** като в .js файла:

- **html-snippet.html:** форма; резултатът се показва като суров HTML и като рендериран.
- **nearest-point.html:** координатна равнина в canvas. Първият клик задава локацията, следващите добавят точки, а точките могат да се редактират в списък.
- **geo-area.html:** карта с Leaflet и OpenStreetMap. С кликове се чертае полигон и се изчислява площта.

**Хванат бъг:** в nearest-point променлива с име `location` на най-горното ниво на скрипта се сблъсква с вградения `window.location`. Браузърът хвърля SyntaxError и страницата не работи. Агентът го забеляза при преглед, преименува променливата на `userLoc` и провери синтаксиса на скриптовете в трите страници.

### Етап 5: Редизайн

Заданието беше дизайн, който да впечатли. Решенията:

- **Обща визуална система за трите страници:** светла тема, serif шрифт за заглавията (Instrument Serif), Inter за текста и JetBrains Mono за кода. Всяко упражнение има свой акцентен цвят: синьо, зелено и виолетово.
- **Навигация:** горна лента с табове, която свързва трите сайта в едно цяло.
- **„Под капака“:** на всяка страница се показва реалният изходен код на функцията. Той се чете с `fn.toString()`, така че показаното винаги съвпада с изпълняваното. Има и бутон „Копирай за Judge“.
- **Допълнения:**
  - HTML Snippet: режим „Покажи таговете“ и разбивка на трите извиквания на `printAsHTML`.
  - Nearest Point: кръг на търсене, мерник под курсора, разстояние до всяка точка, остро изображение на Retina екрани.
  - Geo Area: върхове, които се влачат; площ, която се обновява на живо; хектари, декари и периметър; формулата в математически вид.

**Визуална проверка:** headless браузър (Edge) прави screenshot на всяка страница на ширина 1440px и 390px (телефон), а агентът преглежда изображенията. Така бяха хванати и поправени три проблема:

1. В Nearest Point надписите се застъпваха при точките от примера. Равнината е приближена, а надписите са преместени.
2. Светлият слой на картата (CARTO) показваше „API KEY REQUIRED“. Заменен е с OpenStreetMap и монохромен CSS филтър.
3. На тесен екран решетките можеше да избутат съдържанието извън екрана. Поправено с `minmax(0, 1fr)`.

### Етап 7: Инцидент: 404 на трите сайта

**Симптом:** след push в GitHub трите адреса започнаха да връщат 404.

**Причина:** проектите във Vercel бяха свързани с това repo. Всеки push се публикуваше автоматично като production, но Vercel публикуваше **корена** на repo-то, а там няма `index.html`.

**Диагностика:** HTTP заявките показаха `X-Vercel-Error: NOT_FOUND`. Това значи, че deployment-ът съществува, но файлът липсва. Vercel API показа, че проектът е свързан с GitHub и че Root Directory е празна.

**Поправка:** на всеки проект е зададена Root Directory `Functions-Objects-Events/vercel/<име>`, след което е публикуван наново. Трите адреса отново връщат 200. Оттук нататък всеки `git push` публикува правилната папка.

**Извод:** публикуването е успешно чак когато сайтът отговаря на живия адрес. Статус „Ready“ във Vercel не е достатъчен.

## Изводи

- **AI агентът греши, а проверката го хваща.** Сблъсъкът с `window.location`, слоят с ключ и застъпените надписи не се виждат при четене на кода. Видяха се при стартиране, при HTTP заявка и при screenshot.
